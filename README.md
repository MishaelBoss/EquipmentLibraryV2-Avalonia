# EquipmentLibrary V2 (ELA V2)

Кроссплатформенное десктопное приложение для учёта лабораторного оборудования, средств измерений (СИ)
и испытательного оборудования (ИО). Переработанная версия прежней системы на **Avalonia UI**,
**.NET 10** и **PostgreSQL**.

> **Статус:** приложение в разработке. Аналитика пока на демо-данных, экспорт в PDF/Excel
> не реализован — подробности в разделе [«Текущее состояние»](#текущее-состояние).

## Возможности

### Учёт оборудования

- **Аналитика** — сводные диаграммы по СИ, СДК и ИО (всего единиц, проверено, не проверено, нет калибровки).
  ⚠️ Пока оформлена на **демо-данных**: значения захардкожены в `AnalyticsPageUserControlViewModel` и к БД не подключены
- **Библиотека** — общая таблица оборудования с поиском (наименование, модель, серийный и инвентарный номер)
  и фильтром по типу; поиск с задержкой ввода (debounce)
- **Рабочая область** — быстрая регистрация оборудования (тип, наименование, модель, серийный и инвентарный
  номер, год выпуска, параметры) и счётчики по объектам учёта
- **Журнал измерений (СИ)** — таблица и поиск по данным из БД; кнопки экспорта в **PDF**/**Excel** есть в интерфейсе,
  но пока не реализованы (заглушки, только пишут строку в лог)
- **Реестр испытательного оборудования (ИО)** — таблица и поиск по данным из БД; экспорт в **PDF**/**Excel** — так же заглушки

### Пользователи и доступ

- **Авторизация** — логин и пароль, проверка через `crypt()` PostgreSQL (`pgcrypto`, bcrypt)
- **Ролевая модель** — Администратор, Инженер, Пользователь; видимость разделов зависит от роли
- **Автовход** — сессия на 7 дней; токен хранится в `login.cookie`, в БД — только его SHA-256
  (`public.user_sessions`). Токен проверяется при каждом запуске и раз в 10 секунд; при выходе отзывается.
  Пересоздание БД или удаление/деактивация пользователя автоматически завершают сохранённую сессию
- **Панель администратора** — список пользователей, поиск, фильтры «активные/неактивные», добавление и
  редактирование, смена статуса, сброс пароля с копированием в буфер обмена, удаление с подтверждением
- **Первый запуск** — если в БД нет пользователей, приложение предлагает создать администратора

### Интерфейс

- **Тёмная тема** — единый стиль для окон, страниц и диалогов
- **Уведомления** — панель справа и всплывающие тосты (успех, ошибка, предупреждение, информация);
  успешные и информационные тосты скрываются автоматически через 5 секунд
- **Анимации** — плавная смена страниц, появление/уход тостов, выезжающая панель уведомлений,
  переходы при наведении и нажатии кнопок
- **Настройки** — логирование, расположение папок экспорта, проверка обновлений, подключение к БД
  с тестом соединения
- **Проверка обновлений** — сравнение версии с манифестом, окно с описанием новой версии
- **Режим разработчика** — индикатор в статус-баре в Debug-сборке

## Текущее состояние

Приложение работает не полностью: часть экранов и кнопок пока являются заготовками интерфейса.
Ниже — что именно ещё не доделано, чтобы не было ложных ожиданий.

### Работает с реальными данными

- Авторизация, автовход, роли и панель администратора
- Библиотека оборудования (чтение из БД, поиск, фильтр по типу)
- Рабочая область (регистрация оборудования — реальный `INSERT` в БД, счётчики)
- Журнал измерений и Реестр ИО (чтение из БД, поиск)
- Настройки, проверка обновлений, логирование, уведомления

### Пока не реализовано

- **Аналитика — только для вида.** Все числа и сегменты диаграмм захардкожены
  (`SiTotal = 120`, `SdkTotal = 30`, `IoTotal = 55` и т.д.) в
  `ViewModels/Pages/AnalyticsPageUserControlViewModel.cs`. Реальных запросов к БД нет,
  данные не обновляются и не зависят от содержимого библиотеки.
- **Экспорт в PDF и Excel отсутствует.** Кнопки «PDF» и «Excel» на страницах «Журнал измерений»
  и «Реестр испытательного оборудования» — заглушки: обработчики `DownloadPdf()` / `DownloadExcel()`
  лишь пишут в лог `Download PDF (stub)`. Файлы не создаются. Библиотеки QuestPDF и ClosedXML
  подключены в проекте, но в этих командах ещё не используются.
- **Настройка «Расположение папок»** сохраняет путь, но пока не влияет на выгрузку — выгружать нечего
  (см. пункт про экспорт).

## База данных

Схема создаётся автоматически при старте приложения: `MigrationRunner` через **DbUp** создаёт базу
(`EnsureDatabase`) и применяет встроенные миграции из [`Migrations/`](EquipmentLibraryV2-Avalonia/Migrations)
с учётом журнала `schemaversions`.

- `0001_InitialSchema.sql` — таблицы `user_type`, `users`, `equipment_type`, `equipment`, `maintenance_log`
  и справочные данные
- `0002_UserSessions.sql` — таблица `user_sessions` для серверной проверки автовхода

Чтобы добавить изменение схемы, положите новый файл `000N_Название.sql` в `Migrations/` — он применится
один раз при следующем запуске. Файл [`db.sql`](db.sql) в корне — старый дамп, приложением не используется.

Параметры подключения задаются в окне **Настройки → Подключение** и хранятся в
`%LOCALAPPDATA%\EquipmentLibraryV2_Avalonia\settings.json`; пароль шифруется (`SettingsProtector`,
ключ — `settings.key` рядом с файлом настроек).

## Настройки

| Раздел | Что настраивает |
|---|---|
| Логирование | Открытие папки с логами |
| Расположение папок | Каталог выгрузки отчётов и режим «сохранять в корень папки» (путь сохраняется, но пока не используется — экспорт не реализован) |
| Обновления | Проверка новых версий при запуске |
| Подключение | IP, порт, БД, пользователь, пароль + тест соединения |

Изменения применяются по кнопке **Применить**; подключение к БД тестируется без сохранения.

## Логирование

Serilog пишет в `%LOCALAPPDATA%\<имя_процесса>\logs\`:

- `main-log-dd_MM_yyyy.txt` — все события, хранится 14 дней
- `errors-log-dd_MM_yyyy.txt` — только Warning/Error/Fatal, хранится 7 дней

Дополнительно логи дублируются в консоль. Необработанные исключения приложения и задач логируются как
`Fatal`/`Error`.

## Разработка

Проект следует паттерну **MVVM** с source-генераторами `CommunityToolkit.Mvvm`.
Навигация и межкомпонентное взаимодействие — через `WeakReferenceMessenger` (сообщения в `Messages/`).
Модальные окна построены как наложение слоёв (`OverlayContent`, `TopOverlayContent`) в `MainWindowViewModel`.
Уведомления отправляются сообщением `ShowOrHideNotification` и обрабатываются в `MainWindowViewModel`.

Заглушки (аналитика на демо-данных, экспорт) помечены в коде комментариями и логами вида `(stub)` —
по ним проще найти места, которые ещё предстоит реализовать.

```bash
dotnet build
dotnet run
```

Не используйте `dotnet build -t:Compile` для проверки: при этом пропускается прекомпиляция XAML,
и приложение падает с ошибкой `No precompiled XAML found`.
